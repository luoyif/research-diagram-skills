## 跨环境渲染的准确边界

Mac未安装可用LibreOffice，因此没有声称在Mac完成PowerPoint原生应用打开检查。PPT预览通过损失为零的OOXML部件传递后在工作容器渲染；逐部件哈希核对一致，重新打包的ZIP时间戳不作字节一致承诺。容器字体匹配使用已安装的CJK字体，不能把该预览说成与Mac宋体像素相同。

三个PPT包的部件集合SHA256（排序后的“部件路径+该部件SHA256”清单）：

- feedback-loop：`cce9ef7a74fcf30b29f9bf6b65888b20c47117ecf53aa976ad488764153946f4`
- nested-architecture：`65064b5a2f480910057f62a21aaf455619a4c5bc7708d2b5caaf5f6a7801a428`
- reference-reconstruction：`ea32fccf39a7ca2284c5c7bfcce1d848e03b9b966fa1b801f00e0288cd5c848f`

核对结果：闭环反馈走外侧并返回生成节点；嵌套卡片未被背景遮挡；双路输入分别进入汇聚节点，未穿过另一分支。所查看的六张实际预览未发现文字裁切、意外连线交叉或主要箭头穿字。

基础build-state仍按各自环境保存真实状态；未把容器外部检查伪装成Mac工具已完成的同目录render/review。正式处理用户新图时必须重新导出和检查，不能沿用这些示例的结果。

## 交付包独立性

发布前使用 `tools/package_skills.py` 生成独立ZIP，并用 `tools/smoke_standalone.py` 在隔离临时目录逐个解压，验证来源、环境检查、示例校验和默认后端构建。具体运行结果放在Release附件 `validation-report.json`，不以本段说明代替实际执行记录。

## 保留限制

图片语义识别由视觉代理或人员清点，不是任意PNG一键可靠转换。基础Scene支持的图元有限，复杂图走已收录上游专项技能；不能删掉难处理元素后宣称完整复刻。几何检查不能代替业务/科研正确性判断，字体宽度及特定软件版本仍需真实预览。PPT多段连线在人工移动节点后需要复查，不承诺与Draw.io双向自动同步。
